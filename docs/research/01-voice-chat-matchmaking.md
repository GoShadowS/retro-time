## 1. Что подтверждено официальной документацией Roblox

### 1.1. Доступность голосового чата — [Ф]

| Условие | Статус | Источник |
|---|---|---|
| Возраст 13+ | Обязательно | [Help Center](https://en.help.roblox.com/hc/en-us/articles/34506487825428-How-do-I-turn-on-Voice-Chat) |
| Проверка возраста: ID-верификация **или** Facial Age Estimation | Обязательно | там же |
| Телефонная верификация | **Не засчитывается** | там же |
| Доступность в регионе | Зависит от региона; «Voice Chat features may not be available in certain regions» | там же |
| Включение по умолчанию | **Выключен**, требуется opt-in | там же |
| Максимум игроков в месте | **≤ 100**, иначе голос не работает | [Voice Chat docs](https://create.roblox.com/docs/chat/voice-chat) |
| Для новых игр с ≤100 игроками | Включён по умолчанию для верифицированных 13+ | там же |

**Следствие для нас:** значимая доля аудитории **физически не может** пользоваться голосом (младше 13, нет возможности пройти проверку, регион без поддержки, не включил). Любая очередь, требующая голос, исключает этих игроков.

### 1.2. Сигнал Voice Chat в матчмейкинге — [Ф]

Официальная документация Roblox, страница [Attributes and signals](https://create.roblox.com/docs/matchmaking/attributes-and-signals):

- Атрибут: **`Is Voice Chat Enabled`** (категориальный) — включён ли у игрока голосовой чат.
- Сигнал: **`Voice Chat`** — это **доля игроков на сервере с такой же настройкой голоса, как у входящего игрока**:

  ```
  voiceChatSignalScore = (число игроков с такой же настройкой голоса) / (число игроков на сервере)
  ```

- **«If a place has voice chat disabled, the Voice Chat signal's weight is 0.»** — если в месте отключён голос, вес сигнала равен нулю.

Страница [Server scoring](https://create.roblox.com/docs/matchmaking/scoring):

- Итог — взвешенная сумма: `ServerScore = Σ Weight_i × SignalScore_i`. Игрок попадает на сервер с **наибольшим** score.
- **Веса по умолчанию:** `Text Chat = 3`, `Voice Chat = 1`, `Device Type = 0`.
- **«In the default Roblox configuration, the Friends signal's weight is greater than the sum of the weights of every other signal. This means that, if available, the joining player is always matched to servers with friends (or players on the same IP address) in them.»**

> **Это ключевой факт.** Вес `Friends` больше суммы всех остальных сигналов. Это значит, что **друзья всегда перекрывают настройку голоса**. Строгое разделение по голосу через встроенный матчмейкинг невозможно в принципе.

### 1.3. Кастомный матчмейкинг — [Ф]

- Кастомный матчмейкинг **доступен всем опытам**; объявление Roblox на DevForum: «Custom Matchmaking is now available to all experiences on Roblox» [объявление, 2025-11-06](https://devforum.roblox.com/t/custom-matchmaking-is-now-available-to-all-experiences-on-roblox/4051419).
- Можно менять веса стандартных сигналов и добавить **до 2 кастомных сигналов**.
- Есть аналитика, включая график **`Voice Chat Ratio`** — доля игроков с включённым голосом на сервере [Ф](https://create.roblox.com/docs/matchmaking/analytics). Это значит, что долю голосовых игроков мы сможем **измерить**, а не угадывать.
- **Ограничение:** «The custom matchmaking configuration would only take affect if you teleport the players to a public server. For reserved server, the teleport is creating a new server for the players, so there's no really matchmaking happening.» [Ф, ответ команды Roblox](https://devforum.roblox.com/t/beta-introducing-custom-matchmaking-with-custom-signals/3598471?page=3).
- **Ограничение:** «players in different variants will be isolated from each other only for matchmaking flows. They can continue to play together when joining through direct server join, party joins, and following friends.» [Ф, FAQ](https://devforum.roblox.com/t/custom-matchmaking-is-now-available-to-all-experiences-on-roblox/4051419).
- **Ограничение:** нельзя управлять моментом создания сервера: «Today, players will only start a server when all the games are full, or potentially when available servers are too far from the player.» [Ф, FAQ](https://devforum.roblox.com/t/custom-matchmaking-is-now-available-to-all-experiences-on-roblox/4051419).

### 1.4. Возможности голосового чата как механики — [Ф]

Это я считаю самой интересной находкой. Официальная документация прямо описывает **командный голос**:

> «To implement Team-based chat where only teammates can hear one another...» — приводится готовый серверный скрипт с `VoiceChatService.UseAudioApi` и `AudioDeviceInput.AccessType` [Ф](https://create.roblox.com/docs/chat/voice-chat).

Также:
- «Voice Chat is **proximity-based by default**, adjusting the volume of participants based on how close they are to each other.» [Ф](https://create.roblox.com/docs/chat/voice-chat)
- «Enabling Voice Chat is **required to use the speech-to-text API**.» [Ф](https://create.roblox.com/docs/chat/voice-chat)
- «Games with voice often see an uplift in engagement, DAU, and spending.» [Ф](https://create.roblox.com/docs/chat/voice-chat)

**[П] Вывод, который я предлагаю обсудить:** в асимметричном хорроре голос — это не только чат, а **игровая механика**. Варианты: выжившие слышат друг друга только на расстоянии (proximity), убийца не слышит никого или слышит всех, крик выдаёт позицию. Это оригинальное решение, которое нельзя списать с референса — и оно ценнее, чем спор про очереди.

## 4. Сравнение трёх вариантов очередей

Исходные данные для оценки:

### Вариант 1. Две отдельные очереди (жёсткое разделение)

**Как реализовать.** Либо два отдельных **места** в universe (одно с включённым голосом, одно с выключенным), либо лобби + `ReserveServerAsync` + `TeleportToPrivateServer` со своей логикой набора.

| | Оценка |
|---|---|
| **Время ожидания** | **Хуже всего.** При двух местах население делится. Для Double Trouble нужно 14 человек в одном сервере; при половинном пуле время набора растёт нелинейно, а риск «недобора» резко увеличивается. |
| **Риск незаполненных матчей** | **Высокий**, особенно для 2v12. Roblox не даёт «подождать, пока наберётся 14» — новый сервер стартует только когда все заполнены или сервера слишком далеко [Ф]. |
| **Доступность для игроков без голоса** | Хорошая, **если** очередь без голоса существует на равных. Но она рискует стать «очередью второго сорта», если в ней больше недоборов. |
| **Игра с друзьями** | **Плохо.** Друзья могут присоединиться друг к другу напрямую, через пати и «follow» даже при разных вариантах матчмейкинга [Ф]. Группа со смешанными настройками голоса **разорвётся**. |
| **PC и мобильные** | Нейтрально. |
| **Разделение действительно строгое?** | **Нет, даже здесь.** Прямое присоединение к серверу, пати и «follow» обходят разделение [Ф]. |

**[П] Дополнительный риск:** два отдельных места = два отдельных вхождения в поиске Roblox; визиты, избранное и рекомендательные сигналы делятся. Для стартующего проекта это заметная цена.

**Как реализовать.** Одно место, голос включён, в кастомном матчмейкинге поднять вес `Voice Chat` выше дефолтного 1. Аналитика даёт график `Voice Chat Ratio` для контроля [Ф].

| | Оценка |
|---|---|
| **Время ожидания** | **Лучше всех.** Население не делится, матчмейкинг работает как обычно. |
| **Риск незаполненных матчей** | **Минимальный.** Один пул на все режимы. |
| **Доступность для игроков без голоса** | Нормальная — они просто попадают в смешанные матчи. |
| **Игра с друзьями** | **Работает.** Друзья остаются вместе. |
| **PC и мобильные** | Нейтрально. |

## 5. Решение

### 5.1. РЕШЕНО (2026-11-08): принят вариант 3 — одна очередь на старте

Уточнения, данные пользователем и зафиксированные здесь:

- **Единая очередь по голосовому чату не означает объединение режимов.** Игроки **не** разделяются по наличию или настройкам голоса — ни в Default, ни в Double Trouble, ни в One Bounce. При этом подбор игроков остаётся обычным **для выбранного ими режима**: разные режимы **не** смешиваются в один матч.
- Голосовой чат остаётся **необязательным дополнением**. Микрофон **не должен быть необходим** для командной игры.
- Вся критически важная информация передаётся **визуальными средствами**; внутриигровые действия и сигналы доступны игрокам без микрофона.
- На старте **не создаются** отдельные места или серверы исключительно для разделения по голосу.
- Собираем аналитику: заполнение матчей, время ожидания, выходы из очереди, популярность режимов, использование голосового чата — **если эти данные доступны**.
- К разделению возвращаемся **только если аналитика покажет спрос и пользу**, без ухудшения поиска матчей. Отдельно проверяем риск долгого ожидания и незаполненных серверов в **Double Trouble на 14 игроков**.
- **Порог для такого решения не придумываем без данных.**

### 5.2. Голос как игровая механика: ОТЛОЖЕНО, НЕ ОТКЛОНЕНО

Решение пользователя от 2026-11-08: сначала прорабатываем основные правила и три режима. До этого **не вводим**:

- proximity-голос;
- отдельные командные голосовые каналы;
- возможность убийцы подслушивать выживших;
- любые другие механики, влияющие на игру через голос.

**После** того как основные правила режимов проработаны — вернуться к сравнению трёх вариантов (обычный чат / proximity-голос / отдельные командные каналы) с оценкой влияния на **баланс, доступность, приватность и игру без микрофона**, и с проверкой актуальных возможностей и ограничений Roblox.

### 5.3. Моя рекомендация (совпала с принятым решением)

**Вариант 3 на старте + обязательный неголосовой информационный слой, затем решение по данным.**

Обоснование:
1. **Матematika заполнения.** Double Trouble требует 14 игроков в одном сервере. Разделение пула напрямую угрожает способности набирать такие матчи — это самый хрупкий из наших режимов.
2. **Жёсткое разделение в Roblox недостижимо средствами матчмейкинга.** Сигнал `Voice Chat` — это доля, а не фильтр; `Friends` доминирует; пати и «follow» обходят изоляцию [Ф, всё подтверждено документацией].
3. **Цена варианта 1 выше, чем кажется.** Два места = два вхождения в поиске и разделённые рекомендательные сигналы.
4. **Неголосовой информационный слой нужен в любом случае** — из-за возрастных и региональных ограничений голоса [Ф].
5. **У нас будет измерение.** График `Voice Chat Ratio` в аналитике [Ф] даст реальную долю голосовых игроков. Решать о разделении лучше по ней, чем до запуска.

**Что предлагаю обсудить вместо спора об очередях:** голос как **механику**, а не как чат. Командный и proximity-голос официально поддерживаются [Ф] — см. раздел 1.4. Для асимметричного хоррора это даёт оригинальные решения, которых нет в референсах.
